# 二十条箴言，先看全文

`import this`——彩蛋模块，用 ROT13 藏在标准库里。全文如下，原样输出：

```python
import this
```

箴言不是规则，是**取舍时的提示**。挑六条，配反例。

## 六条最常被违反的

**Explicit is better than implicit.** 显式优于隐式。

```python norun
# 隐式：counts 从哪来的？要往上翻多久？
from utils import *

# 显式：来源写在脸上
from utils import word_count
```

**Errors should never pass silently.** 错误永远不要静默通过。

```python
try:
    save(data)
except Exception:
    pass          # ← 数据丢了，没有任何痕迹
```

正确姿势是捕获具体异常并处理或记录（第 25 课）。

**Flat is better than nested.** 扁平优于嵌套。

```python norun
# 四层缩进，读者在第四层已经忘了第一层
if config:
    if config.enabled:
        if config.mode == "batch":
            if config.size:
                run(config.size)

# 早返回拉平一层层
if not config or not config.enabled:
    return
if config.mode != "batch" or not config.size:
    return
run(config.size)
```

**Readability counts.** 可读性计数。

```python norun
# 变量名是给三个月后的自己的
d = {k: v["n"] for k, v in x.items() if v["n"]}
```

**There should be one obvious way to do it.** 一种明显的方式。

同一件事有 `x if c else y`、字典分发、函数式三种写法时，选团队最常出现的那种——**一致性本身就是可读性**。

**If the implementation is hard to explain, it's a bad idea.** 难解释的实现是坏主意。

> [!why] 特例条款：practicality beats purity
> Zen 自己说"实用胜过纯粹"。测试里的局部 hack、一次性脚本的快捷写法，都可以接受——**判断标准是这段代码还要活多久、给谁读**。活三个月、只给自己看，Purity 可以让位。

## 小结

- Zen 是取舍提示不是规则，`import this` 随时可见全文。
- 最高频违反：隐式来源、吞异常、深嵌套、难读的名字。
- 特例条款：practicality beats purity——按代码的寿命与读者裁量。
- 代码评审时把 Zen 当 checklist：每条都能转化成一个提问。
