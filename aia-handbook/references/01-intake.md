# 阶段 0 · 立项

> 目标：产出一份能约束后面所有阶段的 `book.yaml` 和 `00-positioning.md`。
> 立项不是填表，是**逼取舍**。这一小时省下来，后面要用十倍返工补。

## 一、六个必答问题

按顺序问，每个都要拿到能写进文件的具体答案。

### 1. 读者是谁？他现在能做什么？

不合格：「有一定基础的开发者」。
合格：「能调通大模型 API、但说不清自己应用效果好不好的后端工程师」。

**判据：能不能举出一个具体场景。** 举不出来就是没想清楚。

### 2. 读完之后，他能做什么？

必须用**可验收的动词**开头：能搭出、能判断、能排查、能交付。

| 不合格 | 合格 |
| --- | --- |
| 理解 RAG 的原理 | 能给一份 PDF 手册搭出带引用的问答服务 |
| 掌握 Agent 开发 | 能判断一个需求该不该用 Agent，并说出理由 |
| 了解评测方法 | 能搭一个 20 题的评测集并跑出基线 |

「理解」「了解」「掌握」全部不合格——它们无法验收，也就无法写。

### 3. 这本书**不讲**什么？

至少要拿到 5 条。这条最容易被跳过，也最能暴露定位是否清晰。

常见的好答案：「不讲模型训练」「不讲 K8s 深水区」「不讲商务谈判」。

**说不满 5 条，说明范围没定，回去想。**

### 4. 和同类内容差在哪？

一句话。答「更系统」「更实战」不算答案——所有书都这么说。

合格的差异是**结构性的**：「别人讲技术不讲交付，这本书每个技术点都回答客户会不会验收」。

### 5. 多少章？每章多少字？

用反推法：**每章能不能讲透一件事？**

- 讲不透 → 拆章，或砍内容
- 讲得太空 → 合并章

经验：`practical` 每章 5000–7000 字讲一个可交付的能力点。
30 章的书不是"内容多"，是"有 30 个独立能力点"。

### 6. 有没有贯穿项目？

| 选 | 适用 |
| --- | --- |
| `capstone` | 全书围绕一个项目推进，每章都要动它 |
| `running-example` | 一个例子跨若干章复用，不要求每章推进 |
| `none` | 各章独立 |

`project` 类型强制 `capstone`。有项目名就现在定，**冻结后不得改名**。

## 二、三个反问（用来判断该不该写）

1. **这本书如果只能留 3 章，留哪三章？** 答不出说明没有主线。
2. **读者为什么不直接看官方文档？** 答「更系统」不算。
3. **你能不能立刻画出这本书的能力阶梯？** 画不出说明还没想清学完能干嘛。

三条里答不出两条，建议先写一篇长文试水，不要直接开书。

## 三、产出

### `book.yaml`

从 `templates/book/book.yaml` 复制，逐字段填。**每个字段都要有理由**，
填不出来的就删掉，别留着占位。

关键字段：

```yaml
genre: practical          # 单值或 [主类型, 副类型]
spine: capstone           # 决定全书组织方式
scale: {chapters: 10, words_per_chapter: [4500, 6000]}
audience: {who: "...", level: intermediate, prerequisite: [Python 基础]}
```

`prerequisite` 里写进去的东西，正文不再解释。**所以不要多写**——
写了「Python 基础」，就不能再花一节讲什么是函数。

### `00-positioning.md`

固定六个小标题，每个 ≤200 字：

```markdown
## 一句话定位
## 目标读者
## 学习目标（读完能做到什么）
## 范围边界（讲什么 / 不讲什么）
## 与同类的差异
## 技术栈与版本
```

「学习目标」必须与问题 2 的答案逐条对应，一条不多一条不少。

## 四、验收清单

- [ ] `audience.who` 能让人在脑海里浮现一个具体的人
- [ ] 学习目标全部以可验收动词开头
- [ ] 「不讲什么」≥ 5 条
- [ ] 差异点不是「更系统 / 更实战 / 更深入」
- [ ] 章数 × 每章字数与主题复杂度匹配
- [ ] `spine: capstone` 时项目名已定
- [ ] `book.yaml` 能通过 `schemas/book.schema.json` 校验

## 五、常见错误

| 错误 | 后果 |
| --- | --- |
| 读者写「零基础到精通」 | 两头都不讨好，每章都在做取舍 |
| 学习目标写「掌握 X」 | 无法验收，写完不知道达没达到 |
| 不讲什么留空 | 书会膨胀到 60 章，然后烂尾 |
| 先定 30 章再想内容 | 一半章节会没东西可写，靠注水撑 |
| 项目名随手起 | 冻结后改一次，全书的代码路径和图都要改 |
