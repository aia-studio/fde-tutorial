# genre: interview · 面试通关

> 覆盖层。只写与 `_core.md` 不同的部分。
> 适用：把知识点转成「能在 45 分钟里讲清楚」的答案。
> 读者目标是「被追问时也答得住」。

## 1. 判定标准

选 `interview` 的标志：

- 有明确的评价者在场，答案会被打分
- 同一个问题有及格、良好、优秀三档回答
- 真实场景里一定会有追问

如果读者读完是为了做事而不是为了答题，那是 `practical` 或 `principle`。

## 2. 章节骨架（排他 · 主类型决定）

```
① 考点头块（引用块）
   > 考察：<这是考什么能力，不是考什么知识>
   > 出现频率：高 / 中 / 低｜难度：★★★☆☆
   > 一句话答案：<30 字以内，能在面试里脱口而出的版本>
② 考点地图（这个考点与相邻考点的关系，面试官可能往哪跳）
③ 真实提问（面试官原话，含语气；预埋本问题会引出的追问）
④ 分层解析（三档答案：及格 / 良好 / 优秀，各自对应什么水平）
⑤ 追问链（三层追问，每层给「考察意图 + 答到什么程度算过」）
⑥ 高频错误（候选人常答错的点 + 面试官听到时会怎么想）
⑦ 自测（限时 3 分钟作答，附评分标准）
⑧ 下一考点（1–2 句）
```

第 ④ 段和第 ⑤ 段是这一类独有的。**没有分层的答案是背诵，没有追问链的答案是自嗨。**

第 ① 段的「一句话答案」必须能独立成立——读者哪怕只记住这一句，
也不至于在这个问题上翻车。

## 3. 标注体系

| 标注 | 用途 |
| --- | --- |
| 【考点】 | 这道题真正在考什么（往往不是表面问题） |
| 【追问】 | 面试官接下来大概率会问什么 |
| 【加分项】 | 主动提到会显著提高评价的内容 |
| 【减分项】 | 说了会掉分的表述，附替代说法 |
| 【面试官视角】 | 站在评价者角度，这个答案被怎样解读 |
| 【陷阱】 | 看似正确但会被追问到崩的答法 |
| 【版本】 | 答案随技术版本变化的部分 |
| 【待确认】 | 不同公司口径不同的地方 |

【面试官视角】是这一类最有价值也最难写的标注。它要求写手跳出「我会什么」，
去想「对方听到这句话会怎么判断我」。

## 4. 与 principle 的区别

| 维度 | principle | interview |
| --- | --- | --- |
| 组织单位 | 机制 | 考点 |
| 骨架第 4 段 | 正文各节 | 分层答案 |
| 骨架第 5 段 | 权衡表 | 追问链 |
| 收尾 | 延伸阅读 | 限时自测 |
| 成功标准 | 判断正确 | 在压力下表达清楚 |
| 篇幅 | 6000–8000 字 | 3000–5000 字 |

**判据一句话：** 有没有人在对面打分？有是 interview，没有是 principle。

## 5. 代码要求

- 只有「代码题」类考点需要代码，其余以文字答案为主
- 代码片段 ≤ 20 行，且必须能预测输出
- 输出预测题：先给代码，让读者写下输出，再给答案与解释
- 不要求可运行，但要求结果确定（不含随机、时间、环境依赖）

## 6. 图表要求

- ≥1 张图：决策树（「面试官问到 X 时，往哪条分支走」）或考点关系图
- ≥1 张表：分层答案对照表，或方案对比表
- 图可以比其它 genre 少，但决策树是这一类的高价值图

## 7. 练习要求

| 项 | 要求 |
| --- | --- |
| 形式 | 限时作答（3 分钟），先写再对照 |
| 评分 | 给出三档标准，读者自评落在哪一档 |
| 追问 | 自测题必须附带「如果被追问，你的答案还成立吗」 |

## 8. 反模式（这一类特有）

| 禁止 | 原因 |
| --- | --- |
| 只背答案不讲原理 | 一追问就崩，这正是本书要解决的问题 |
| 只给一种解法 | 面试官常问「还有别的办法吗」 |
| 答案不分层 | 读者不知道自己答到哪一档 |
| 没有追问链 | 真实面试一定有追问 |
| 脱离真实提问语气 | 「请简述 RAG 的原理」不像真人说的话 |
| 承诺「背完就能过」 | 面试是概率事件，这种承诺不可信 |
