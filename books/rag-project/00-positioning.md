# 定位与方向

> 阶段 0 产物 · 本书一切内容的最终裁判标准

## 一句话定位

给要交付 AI 项目的 FDE 与解决方案工程师，按八个阶段走完一个客服问答系统的需求、接入、检索、引用、联调、上线、二期与收尾。

## 目标读者

- **画像**：能写代码、也要面对客户；做过后端交付，但没交付过 RAG 系统。
- **前置知识（最低门槛）**：Python 基础、HTTP 与数据库基本操作、调用过大模型 API。
- **典型场景**：客户签了合同，要求三个月内上线一个能回答工单的问答系统，中间要过四次验收。
- **反面读者（不在服务范围内）**：只想学算法原理的人，请读 principle 那一本。

## 学习目标（读完能做到什么）

1. 能把一句模糊需求拆成客户能签字的验收项。
2. 能按阶段交付：数据接入、检索链路、引用拒答、联调压测、上线复盘。
3. 能识别并记录返工原因，写进复盘与交接文档。
4. 能在上线前用检查清单判断能不能发。

## 范围边界

**这本书讲什么：**
一个真实交付项目的八个阶段：需求、数据、检索、引用、联调、上线、二期扩展、收尾交接。

**这本书不讲什么（至少 5 条）：**
- 不讲模型训练与微调
- 不讲向量数据库的底层实现
- 不讲商务报价与合同条款
- 不讲多模态
- 不讲 Agent 编排
- 不讲大规模分布式部署

## 与同类的差异

不讲「技术怎么做」，讲「交付怎么过验收」：每个阶段都有交付物、验收人、风险登记与复盘。
