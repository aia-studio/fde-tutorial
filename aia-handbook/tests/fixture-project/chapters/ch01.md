## 现场开场

周一上午，客服主管说「做个能回答工单的机器人」。你问她知道什么算做好，她说「反正比现在快」。这句话不能直接开工，先要把它变成一个能验收的交付物。

### 1.1 把模糊需求拆成验收项

> 路径：必读

**决策**：先不做模型，用关键词匹配跑通链路。理由是现在缺的不是效果，是可演示的完整验证。

**实施**：把「回答工单」拆成读数据、找相似、出答案三步，每步给一个可观察结果。

**验证**：用十条真实工单试，至少八条能返回原文片段，才算通。

```python
def answer(q: str, rows: list[dict]) -> str:
    hit = [r for r in rows if q[:2] in r["desc"]]
    return hit[0]["desc"] if hit else ""
```

### 1.2 搭建可运行骨架

> 路径：必读

**决策**：入口先写死，数据后接。骨架只需要能被调用，不需要正确。

**实施**：建 `app/main.py` 与 `app/answer.py`，跑通一次空数据调用。

**验证**：`python -m app.main` 不报错，打印一行占位答案。

| 检查项 | 通过标准 | 谁来验 |
| --- | --- | --- |
| 入口可调用 | 不抛异常 | 你自己 |
| 占位答案 | 打印非空字符串 | 你自己 |

### 1.3 接通样例数据

> 路径：选读

**决策**：先用客服导出的 csv，不碰生产库。样例数据足以支撑演示。

**实施**：读 csv 时先试 utf-8-sig，失败再换 gbk。两种编码都写进脚本注释。

**验证**：打印前三条工单，字段完整、无乱码。

```python
import csv

def load(path: str) -> list[dict]:
    with open(path, encoding="utf-8-sig") as f:
        return list(csv.DictReader(f))
```

### 1.4 阶段验收演示

> 路径：必读

**决策**：演示只讲一条链路，不铺功能。观众只需要看到问题进、答案出。

**实施**：准备三条工单，一条必中、一条近义、一条查不到，用来展示边界。

**验证**：主管能指着屏幕说「这条对、这条不对」，验收才算完成。

【验收】客户说「比现在快」不算验收。必须落成「十条里八条返回原文片段」这样的句子。

| 演示样本 | 期望结果 | 实际结果 |
| --- | --- | --- |
| 必中 | 返回原文 | 通过 |
| 近义 | 返回相近原文 | 观察 |
| 查不到 | 明确说没找到 | 待补 |

## 阶段交付物

| 交付物 | 验收标准 | 谁来验收 |
| --- | --- | --- |
| 最小问答脚本 | 十条工单至少八条返回原文片段 | 客服主管 |
| 演示录屏 | 三分钟内跑完一次问答 | 项目负责人 |
| 数据说明 | 标注样例来源与字段 | 你自己 |

## 复盘

**做对了什么**：先跑通链路再谈模型，避免一开始陷进选型。

**做错了什么**：样例只取了一个来源，字段差异被低估。

**下次怎么改**：接数据前先抽样三个来源，确认字段映射再写代码。

## 风险登记

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 样例不具代表性 | 演示通过、上线失败 | 补两个来源 |
| 验收标准含糊 | 反复返工 | 每次验收前写死标准 |
| 编码不统一 | 读取乱码 | 固定 utf-8-sig 并留回退 |
