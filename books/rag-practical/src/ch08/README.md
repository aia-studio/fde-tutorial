# ch08 运营与迭代

前置：`data/ops/` 下有三份样例数据——`feedback.jsonl`（反馈导出）、
`corpus_change.jsonl`（语料变更单）、`badcase.jsonl`（上一个命令的产物）。
字段与线上导出一致，条数是样例规模。

```bash
cd src
python -m ch08.badcase    # 反馈 → badcase，含去重与失效判定
python -m ch08.reindex    # 变更集 → 增量还是全量 → 校验 → 原子切换
python -m ch08.release    # 两版对照 + 灰色发布分桶
python -m ch08.report     # 合成月报，落到 data/ops/monthly-report.md
```

七条误拒的共同点是客户用了口语：「屏幕一片黑」不是「黑屏」，「洒了水」不是「进水」。
这类问题的证据就在前五，被范围判断挡在门外，所以动作是调阈值而不是补语料。

  新增 T-1049
  修改 T-1017
  下线 T-1020

```

增量只碰新增与修改的两条；下线的那条从快照里移除，不需要重新嵌入。
切换用的是同一分区上的 `os.replace`，读到的要么旧库要么新库，没有中间态。

演示用复制代替建索引，为的是把校验与切换两步单独跑通；
真实流水线里，建索引命令先在暂存库上跑完，再进校验，顺序不能反。

答对 +3，会话通过 +2，误拒 +0，p50 +4.3ms

答对涨了三轮，代价是每轮多一次检索，p50 大约翻倍。
耗时会随机器抖动，绝对值不用记，只看两版的比值。

## 结论

- 本月最主要失效是「误拒」，7 条，占 badcase 的 7/10。
- 会话版比单轮版多答对 3 轮，会话通过多 2 条。
- 全量题库只有 3 条会话，涨几条只能看方向，下月扩到十组以上。
```

样例只有十四条反馈，够验证流程，不够下结论。
真实运营里这份报表的分母应该是当月全部会话，不是有反馈的那部分。
