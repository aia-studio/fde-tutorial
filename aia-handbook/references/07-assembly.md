# 阶段 6B · 装配（统稿收尾）

> 与 `06-review.md` 同属阶段 6：06 在前（机检 / 波次整合 / 全书统稿），本文在后（产出 `final/`）。
> 目标：把散落的章节变成一个**像书的东西**。
> 装配不是拼文件，是把书的外围补上——没有外围，三十章就是三十篇文章。

## 一、`final/` 的结构

```
final/
├── README.md              书索引：目录、阅读路径、如何跑代码
├── 00-preface.md          前言（第二稿，已回填真实数字）
├── ch01.md … chNN.md      正文章节（装配产物，不再单独编辑）
├── assets/                图产物副本（自包含：整包可独立分发）
├── appendix-a-glossary.md 术语表（自动生成）
├── appendix-b-references.md 参考文献（自动生成）
├── appendix-c-paths.md    阅读路径表（自动生成）
├── appendix-d-toolbox.md  工具箱（半自动）
├── appendix-e-faq.md      常见问题（半自动）
├── 99-afterword.md        结语
└── LICENSE                从 book.yaml 的 license 生成
```

**自包含：** `assets/` 复制进 `final/`，正文图路径由 `../assets/...` 重写为 `assets/...`。
这样 `final/` 整包拷走、zip 分发都不会裂图。复制与重写由 `scripts/assemble.py` 负责。

`final/` 里的文件**不再手改**。要改就改源文件重新装配，否则下次装配会覆盖。

### 产物清单

| 产物 | 来源 | 方式 | 缺失时 |
| --- | --- | --- | --- |
| `README.md` | `book.yaml` + `02-toc.md` + 阅读路径 | 自动 | 报错 |
| `00-preface.md` | `00-positioning.md` + 真实统计 | 半自动：结构自动、措辞可改 | 报错 |
| `chNN.md` | `chapters/chNN.md` | 自动 + 路径重写 | 报错 |
| `assets/**` | `assets/**` | 全量复制 | 缺图报错 |
| 附录 A 术语表 | `.book/glossary.json` | 全自动 | 空账本时留占位 |
| 附录 B 参考文献 | `.book/claims.jsonl` 的 `source` | 全自动 | 留占位 |
| 附录 C 阅读路径 | 各章 `> 路径：` 标注 | 全自动 | 留占位 |
| 附录 D 工具箱 | `book.yaml` 的 `stack` + requirements | 半自动：用途需补一句 | 留占位 |
| 附录 E FAQ | 各章「常见坑」+ `promises` 的 `dropped` | 半自动：合并同类项 | 留占位 |
| `99-afterword.md` | `.book/ladder.jsonl` 末章 `after` | 半自动 | 留占位 |
| `LICENSE` | `book.yaml` 的 `license` | 自动 | 报错 |

**"留占位"不等于通过。** 占位文件里会写 `<!-- TODO: ... -->`，装配校验会把它列成待办。

## 二、前言要写两次

### 初稿（阶段 1 之后，第 1 波之前）

作用是逼你把话说明白。写不出来说明定位没定好，此时返工最便宜。

初稿只回答五个问题，不管篇幅：

1. 这本书给谁看
2. 读完能做什么
3. 这本书**不讲**什么
4. 怎么读（三条路径）
5. 代码怎么跑起来

### 终稿（装配时）

初稿里所有模糊数字换成真实数字：「约 30 章」→「29 章」，「上百张图」→「142 张图」。

### 前言必须含的五项（闸门会查）

| # | 内容 | 一致性要求 |
| --- | --- | --- |
| 1 | 读者画像与前置知识 | 与 `book.yaml` 的 `audience` 不矛盾 |
| 2 | 三条阅读路径 | 与附录 C 的路径表一致 |
| 3 | 本书不讲的 | 与 `00-positioning.md` 的范围边界一致 |
| 4 | **标注体系说明** | 书里用到的每种【】都要解释 |
| 5 | 代码运行约定 | 三条命令能跑起来，Mock 模式写清楚 |

第 4 项最常被漏。书里用了【代价】【待确认】【排查】，读者第一次见只会当成装饰。
**自定义标记不解释，等于全书多了一批噪音。**

## 三、附录：四个自动，三个半自动

| 附录 | 来源 | 方式 |
| --- | --- | --- |
| A 术语表 | `glossary.json` | 全自动：`zh / en / def / 首现章` |
| B 参考文献 | `claims.jsonl` 的 `source` 去重 | 全自动：按出现顺序编号 |
| C 阅读路径 | 各章小节的 `> 路径：必读/选读/参考` | 全自动 |
| D 工具箱 | `book.yaml` 的 `stack` + `src/**/requirements.txt` | 半自动：补一句用途 |
| E FAQ | 各章「常见坑」汇总 + 承诺账本 `dropped` 项 | 半自动：合并同类项 |

**维护账本的回报就在这一节。** 没有 `glossary.json`，术语表要手工整理两天；
有了它，附录 A 是一次格式转换。

## 四、结语

只有一条约束：**结语声称「读完你能做到 X」，X 必须逐条来自 `ladder.jsonl` 的末章 `after`。**

不许新增 ladder 里没有的能力。这是全书唯一允许"概括"的地方，
但概括的内容必须能追溯到具体条目。

写得短一点。读者读完 500 页，不需要再看两千字的总结。

## 五、`README.md`

书的第一入口，必须回答三个问题：

```markdown
# 书名

一句话说明这本书讲什么、给谁看。

## 怎么读
- 快速路径：Ch01 → Ch03 → Ch08 …
- 完整路径：顺序读
- 复习路径：各章自查清单 + 常见坑

## 怎么跑代码
git clone …
cd src && uv sync
python -m ch01.demo

## 目录
| 章 | 标题 | 一句话 |
```

`capstone` 类书还要给快照列表：

```markdown
## 从任意节点开始
- `capstone/ch05` 数据接入完成
- `capstone/ch10` 检索链路跑通
```

## 六、装配后必须做的三件事

1. **随机抽三章，从头读一遍。** 机检全过不代表读得下去
2. **照着 README 的命令实跑一次。** 在自己的机器上，不借助已有环境
3. **检查所有 `final/` 内的相对路径。** 装配时 `assets/` 已复制进 `final/`、
   图路径已重写为 `assets/...`，但仍要扫一遍有没有漏网的 `../`——它们会在整包分发时裂图

第 3 条是装配阶段最常见的翻车点。`check.py` 默认检查 `chapters/` 下的路径，
`final/` 的路径正确性由 `assemble.py` 的装配后校验负责（有不可达路径即报错）。

## 七、最后一道验收

```bash
python scripts/check.py --book <书目录>
```

注意这个命令检查的是 `chapters/` 下的源文件，不是 `final/`。
`final/` 的路径正确性由 `assemble.py` 装配后自动扫描（见上一节第 3 条）。

- [ ] 全书 error = 0
- [ ] 每章字数在 ±25% 内
- [ ] `promises.jsonl` 无 `open`
- [ ] 术语表条目数 ≤ `max_core_terms`
- [ ] 前言五项齐全
- [ ] 结语能力清单 ⊆ ladder 末章 `after`
- [ ] README 的命令实跑通过

全过之后，这本书才算完成。**任何一个"差不多"，都会在读者那里变成"这本书没写完"。**
