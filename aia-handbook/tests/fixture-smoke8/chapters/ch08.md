## 场景开场

周一上午，客服主管把一份表格发到群里。她说同事每天要翻半小时才能找到相似问题。你手上只有一台装了 Python 的笔记本，先要把这条路走通。

### 8.1 先确认目标

> 路径：必读

先把目标写成一个能观察的结果。你要的不是功能列表，而是一条能跑通的路径。路径通了，功能才有地方加。判断标准只有一条：用真实数据能不能跑出结果。

| 目标 | 通过标准 | 先不做 |
| --- | --- | --- |
| 能读 | 数据进得来 | 接生产库 |
| 能找 | 命中一条 | 向量检索 |
| 能答 | 有原文 | 调大模型 |

### 8.2 搭最小骨架

> 路径：必读

骨架不需要正确，只需要能被调用。入口先写死，数据后接。这样你改任何一段，都能立刻看到影响。

【注意】骨架阶段不要接生产库，先把样例跑通。

```python
def run(q: str) -> str:
    return q.strip()
```

### 8.3 接上数据

> 路径：选读

样例数据先跑通，再换真实来源。换源时只改配置，不改业务代码。这样演示环境和真实环境才能共用一套逻辑。

| 来源 | 风险 | 适用 |
| --- | --- | --- |
| 样例文件 | 不具代表性 | 先跑通 |
| 只读从库 | 延迟 | 本阶段 |

### 8.4 跑通验收

> 路径：必读

验收要可重复。固定一组样本，每次跑同一套检查。结果不一致，就先查数据，再查代码。顺序反了，会把数据问题当成代码问题。

| 检查项 | 通过标准 |
| --- | --- |
| 能读 | 打印三条 |
| 能找 | 至少一条 |
| 能答 | 含原文 |

## 动手练习

1. 用样例跑一次，确认输出含原文。验收：终端打印三条命中。
2. 换一个数据源，观察差异。验收：输出结构一致。

## 常见坑

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 乱码 | 编码不对 | 换 utf-8-sig |
| 空结果 | 关键词太少 | 加同义词 |
| 半通 | 没取正文 | 检查取正文 |
