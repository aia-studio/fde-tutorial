# 定位与方向

> 阶段 0 产物 · 本书一切内容的最终裁判标准

## 一句话定位

给能调通大模型 API、但没做过检索的后端工程师，用八章搭出一个带引用、能拒答、可评测、能持续修的客服问答服务。

## 目标读者

- **画像**：能调通大模型 API，但说不清自己应用效果好不好；写过业务后端，没做过检索。
- **前置知识（最低门槛）**：Python 基础、HTTP 与 JSON、调用过大模型 API。
- **典型场景**：客户要求「做个能回答工单的机器人」，你要在两周内交出一个可演示、可验收的版本。
- **反面读者（不在服务范围内）**：要做模型训练、要做大规模分布式检索、只想了解概念的人。

## 学习目标（读完能做到什么）

1. 能搭出带原文引用的问答服务，并在十条真实工单上跑通。
2. 能判断一次召回失败属于切分、向量还是关键词问题，并给出修复顺序。
3. 能搭一个 20 题的评测集，跑出召回率、引用准确率与拒答率基线。
4. 能向客户解释系统边界，并在该拒答时拒答。

## 范围边界

**这本书讲什么：**
从零搭一条 RAG 链路：切分、向量化、检索、引用、拒答、混合检索、评测与上线。

**这本书不讲什么（至少 5 条）：**
- 不讲模型训练与微调
- 不讲分布式向量数据库的运维
- 不讲 embedding 模型的训练细节
- 不讲多模态检索
- 不讲 Agent 编排与工具调用
- 不讲商业化选型与采购

## 与同类的差异

多数 RAG 内容讲「怎么调通」，这本书每章都回答「客户会不会验收」：引用要能对上原文，拒答要有话术，评测要有基线。
