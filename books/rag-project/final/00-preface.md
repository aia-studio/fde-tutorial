# 前言

## 这本书给谁看

- **画像**：能写代码、也要面对客户；做过后端交付，但没交付过 RAG 系统。
- **前置知识（最低门槛）**：Python 基础、HTTP 与数据库基本操作、调用过大模型 API。
- **典型场景**：客户签了合同，要求三个月内上线一个能回答工单的问答系统，中间要过四次验收。
- **反面读者（不在服务范围内）**：只想学算法原理的人，请读 principle 那一本。

## 读完你能做什么

1. 能把一句模糊需求拆成客户能签字的验收项。
2. 能按阶段交付：数据接入、检索链路、引用拒答、联调压测、上线复盘。
3. 能识别并记录返工原因，写进复盘与交接文档。
4. 能在上线前用检查清单判断能不能发。

## 这本书不讲什么

- 不讲模型训练与微调
- 不讲向量数据库的底层实现
- 不讲商务报价与合同条款
- 不讲多模态
- 不讲 Agent 编排
- 不讲大规模分布式部署

## 怎么读

### 快速路径

必读小节 + 每章小结：Ch01 需求澄清与验收标准 → Ch02 数据接入与清洗 → Ch03 检索链路搭建 → Ch04 引用与拒答 → Ch05 联调与压测 → Ch06 上线与复盘 → Ch07 二期扩展 → Ch08 项目收尾与知识转移

### 完整路径

按章顺序通读。

### 复习路径

必读小节 + 各章自查清单 + 常见坑。

## 标注体系

| 标注 | 含义 |
| --- | --- |
| 【代价】 | 这个选择的成本与副作用 |
| 【取舍】 | 两个方案里为什么选这个，放弃了什么 |
| 【待确认】 | 需求或行业做法存在分歧，并列给出 |
| 【排查】 | 出问题时的诊断顺序 |
| 【现场故事】 | 客户/同事的原话、真实反应（虚构但可信） |
| 【返工】 | 做错了、推翻重来的地方，以及原因 |
| 【风险】 | 可能导致返工或验收失败的因素 |
| 【验收】 | 客户/甲方会怎么判断这个交付物合格 |
