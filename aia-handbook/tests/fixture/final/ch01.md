

# Ch01 从零搭一条链路

> 本章解决：怎么在半小时内跑通一次最小问答？

## 场景开场

周一上午，客服主管把一个表格发到群里。表格里有三百条历史工单。她说同事每天要翻半小时，才能找到相似问题的处理办法。你手上没有现成系统，只有一台装了 Python 的笔记本。这个场景要解决的不是模型多聪明，而是能不能先把路走通。

### 1.1 先确认最小可用是什么

> 路径：必读

最小可用不是功能少，而是端到端跑通。你要的是一条完整路径：问题进去，答案出来。功能可以后加，路必须先通。判断标准只有一条：能不能用真实工单试出结果。

| 能力 | 最小实现 | 先不做 |
| --- | --- | --- |
| 读数据 | 读一个 csv | 接数据库 |
| 找相似 | 关键词匹配 | 向量检索 |
| 出答案 | 拼模板 | 调大模型 |

### 1.2 搭一个可运行的骨架

> 路径：必读

先写入口，再填细节。入口能跑，后面每一步都有地方放。骨架不需要正确，只需要可调用。这样你改任何一段，都能立刻看到影响。

```python
def answer(q: str) -> str:
    return "todo"
```

### 1.3 把数据读进来

> 路径：选读

读 csv 只有三行代码，但编码经常出事。先用 utf-8-sig 试，失败再换 gbk。老系统导出的文件多半是 gbk，带 BOM 的导出文件要用 utf-8-sig。两种都试一遍，比猜快。

| 编码 | 适用场景 |
| --- | --- |
| utf-8-sig | 带 BOM 的导出文件 |
| gbk | 老系统导出 |

### 1.4 串起来跑一次

> 路径：必读

把三段拼起来，用一条真实工单试。跑通的标准是输出里有原文片段，而不是空字符串。空字符串说明匹配到了但没取到正文，这属于半通不通。半通比不通更危险，因为你以为它好了。

| 检查项 | 通过标准 |
| --- | --- |
| 能读 | 打印前三条不报错 |
| 能找 | 至少命中一条 |
| 能答 | 输出含原文句子 |

## 本章小结

| 要点 | 结论 |
| --- | --- |
| 最小可用 | 端到端跑通，不是功能少 |
| 骨架先行 | 入口能跑，细节才有地方放 |
| 半通不通 | 比完全不通更难发现 |

## 动手练习

1. 用自带样例跑通一次，确认输出含原文片段。验收：终端打印出三条命中。
2. 换一份 gbk 编码的文件，观察报错并修复。验收：不抛异常。

## 自查清单

- [ ] 能读 csv
- [ ] 能按关键词命中
- [ ] 输出含原文片段

## 常见坑

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 乱码 | 编码不对 | 换 utf-8-sig 或 gbk |
| 空结果 | 关键词太少 | 加同义词 |
| 半通 | 命中却没取到正文 | 检查取正文的逻辑 |
