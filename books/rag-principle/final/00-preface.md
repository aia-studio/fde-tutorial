# 前言

## 这本书给谁看

- **画像**：做过系统设计，正在评估 RAG 方案；不需要亲手写检索代码，但要为方案签字。
- **前置知识（最低门槛）**：了解向量与相似度的基本概念，读得懂伪码。
- **典型场景**：业务方要求「上 RAG」，你要判断它能不能解决问题、代价是什么、什么时候会失效。
- **反面读者（不在服务范围内）**：要找一步步实现教程的人，请读 practical 那一本。

## 读完你能做什么

1. 能判断一个需求该不该用 RAG，并说出理由与替代方案。
2. 能解释一次召回失败属于语义压缩、切分还是查询本身的问题。
3. 能说出混合检索与重排各自在什么条件下才带来增量。
4. 能指出 RAG 的失效边界，并据此划出方案边界。
5. 能读懂一份评测报告，说出它支撑得了什么结论、支撑不了什么结论。
6. 能在检索、长上下文、微调、查询接口之间做出选择，并说明放弃的那几条为什么放弃。

## 这本书不讲什么

- 不讲代码实现与工程细节
- 不讲 embedding 模型的训练
- 不讲具体向量数据库的选型
- 不讲产品与商业模式
- 不讲 Agent 编排与工具调用的工程实现
- 不讲多模态

## 怎么读

### 快速路径

必读小节 + 每章小结：Ch01 RAG 到底解决什么问题 → Ch02 检索的本质 → Ch03 切分的代价 → Ch04 融合与重排 → Ch05 幻觉的定位 → Ch06 RAG 的失效边界 → Ch07 评测能证明什么 → Ch08 替代方案与选择
