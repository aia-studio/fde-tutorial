## 现场开场

主管又来了。她说表格是上周导出的，现在数据和线上不一致，演示时被客户当场指出。你要接真实库，但不能把演示环境搞坏。

### 2.1 先定接入方式

> 路径：必读

**决策**：走只读从库，不直连主库。演示环境的数据一致性可以先放一放，稳定性不能。

**实施**：在配置里加 `DATABASE_URL`，默认指向样例，切库只改一个环境变量。

**验证**：两套配置各跑一次，输出结构一致。

| 方式 | 风险 | 适用 |
| --- | --- | --- |
| 直连主库 | 高 | 不推荐 |
| 只读从库 | 低 | 本阶段采用 |
| 离线导出 | 最低 | 演示兜底 |

【取舍】只读从库有延迟，但换来的是不会误写生产数据。这个阶段延迟可以接受。

### 2.2 封装查询层

> 路径：必读

**决策**：查询逻辑集中到一个模块，不散落在页面里。

**实施**：定义 `fetch(keyword, limit)`，内部处理连接、参数与字段映射。

**验证**：改一次字段名，只改一个文件就能通过测试。

```python
def fetch(keyword: str, limit: int = 10) -> list[dict]:
    sql = "select ticket_no, description from tickets where description like ?"
    return query(sql, (f"%{keyword}%",), limit)
```

### 2.3 处理字段差异

> 路径：选读

**决策**：映射表进版本管理，不写在代码注释里。

**实施**：用 `mapping.yaml` 描述 csv 字段到库字段的对应关系。

**验证**：抽样十条，逐字段比对，差异为零。

| csv 字段 | 库字段 | 备注 |
| --- | --- | --- |
| 工单号 | ticket_no | 主键 |
| 描述 | description | 可能为空 |
| 处理人 | assignee | 样例中没有 |

### 2.4 让验收可重复

> 路径：必读

**决策**：验收脚本化，不靠人工点页面。

**实施**：写 `tests/acceptance.py`，固定十条样本，输出通过率。

**验证**：连续跑三次，结果一致；换库后仍能跑。

```python
def acceptance() -> float:
    cases = load_cases("tests/cases.json")
    ok = sum(1 for c in cases if expected_in(answer(c["q"]), c["want"]))
    return ok / len(cases)
```

【验收】通过率低于八成不交付。标准写在脚本里，不写在会议纪要里。

## 复盘

**做对了什么**：先定接入方式再写代码，避免返工。

**做错了什么**：字段映射发现得太晚，前三节都在用样例字段名。

**下次怎么改**：接库前先拉一份字段清单，再动代码。

## 风险登记

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 从库延迟 | 演示数据落后 | 准备离线兜底 |
| 字段为空 | 答案缺正文 | 映射表标可空 |
| 验收样本泄漏 | 通过率虚高 | 样本不参与调参 |
