## 反直觉开场

一个客服系统上线三周，用户搜「A100 显卡保修」，返回的全是「显卡驱动安装」。团队以为模型不够好，换了更大的 embedding 模型，结果没变。问题不在模型，在检索方式：向量把「A100」压成了一个泛化的「显卡」方向。

### 1.1 向量检索擅长什么

> 路径：必读

向量检索擅长语义相近但字面不同。你说「退货怎么办」，它能找到「如何申请退款」。这种能力来自把句子压成稠密向量，再按距离排序。

| 场景 | 向量是否擅长 | 原因 |
| --- | --- | --- |
| 同义改写 | 擅长 | 语义方向接近 |
| 专有名词 | 不擅长 | 稀有词被平滑掉 |
| 精确数字 | 不擅长 | 数字不构成语义方向 |

### 1.2 三类典型失效

> 路径：必读

失效集中在三类：专有名词、精确数字、极短查询。它们的共同点是「字面即全部信息」，而向量恰恰丢掉了字面。

```text
查询：A100 保修
向量 Top1：显卡驱动安装     ← 语义邻近，字面无关
期望：A100 保修政策          ← 字面精确，语义稀疏
```

### 1.3 为什么切分也会放大失效

> 路径：选读

切分把文档切成块，块越小，上下文越少。专有名词所在的那一句如果被切断，向量就更难定位它。

| 切分方式 | 对专有名词的影响 |
| --- | --- |
| 按固定长度 | 容易切断名词与解释 |
| 按段落 | 保留完整语义单元 |
| 按标题层级 | 名词与所属主题绑定 |

### 1.4 先判断再换模型

> 路径：必读

遇到召回失败，先看失败样本属于哪一类。专有名词和数字优先补关键词检索；语义改写优先调切分与 embedding。换更大的模型通常不是第一步。

【常见误解】换更大的 embedding 模型能解决所有召回问题。模型只改变语义表示，改变不了字面信息的丢失。

| 失败类型 | 第一步 | 不要先做 |
| --- | --- | --- |
| 专有名词 | 补 BM25 | 换 embedding |
| 精确数字 | 加字段过滤 | 加提示词 |
| 语义改写 | 调切分 | 换数据库 |

## 权衡表

| 方案 | 代价 | 适用条件 |
| --- | --- | --- |
| 纯向量 | 专有名词漏召 | 语料口语化、同义多 |
| 纯关键词 | 语义改写漏召 | 术语密集、查询短 |
| 混合检索 | 需要调权重与评测 | 两类失败同时存在 |

## 失效边界

- 语料全是同义口语时，关键词检索几乎不带来增量。
- 查询极短且无明确实体时，混合检索的权重调参收益很低。
- 评测集小于二十条时，任何权重调整都不可信。
- 文档块跨主题时，向量与关键词会同时失准。
