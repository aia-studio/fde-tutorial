# 阶段 6A · 审校与缝合

> 三级：**机检 → 波次整合 → 全书统稿**。越往后越贵，所以别把问题留到后面。

## 一、第一级：机检（每章写完立刻跑）

```bash
python scripts/check.py --book <书目录> --chapter chNN
```

| 结果 | 动作 |
| --- | --- |
| 0 error | 进 `merging`，等本波次整合 |
| 有 error | 进 `repair`，自己修 |
| 修 2 次仍不过 | 转人工。**连续两次修不过是章纲的问题，不是写手的问题** |

修的时候只修报出来的条目，不要顺手改别的——改动越大，越难判断哪一处修好了。

### repair 保留旧稿

每次进入 `repair` 前，把当前稿快照到 `.book/history/chNN/attempt-N.md`，
并在 `state.json` 的 `history` 里记一条（`attempt` / `path` / `at` / `error`）。

理由：连续两次修不过要转人工，人工需要看到「上一次长什么样、错在哪」；
没有快照就只能从 diff 猜。旧稿不参与闸门，也不会被装配。

由 `scripts/state.py --set chNN repair` 自动完成，回滚用 `state.py --rollback chNN`。

## 二、第二级：波次整合（每波结束跑一次）

本波所有章进入 `checking` 后，在下一波发射**之前**跑：

```
术语碰撞 → 跨章重复 → 前向依赖违规 → 指纹偏离
```

### 术语碰撞

同一个概念出现两种定义，或两个术语指同一个东西。

处理：查 `glossary.json` 定权威版本，把另一边改过来。
**不许两边都留着**——读者会在两章之间反复对照，然后怀疑自己。

### 跨章重复

5-gram 重叠超过阈值，通常有两种原因：

- 同一段铺垫被两章都写了一遍（删一处，留引用）
- 同一个例子被复用（要么合并，要么明确说是"复用 Ch05 的例子"）

### 指纹偏离

某章的平均句长、标注密度、图表密度明显偏离第一波的中位数。

不阻断，进 `merging` 队列，由缝合 agent 判断是"这章本来就该不同"还是"写岔了"。

### 修复权责

整合发现的一切问题**都交 agent 修**，不设人工确认。但有两道闸：

| 可以改 | 不可以改 |
| --- | --- |
| 术语用词与定义措辞 | 章纲 |
| 衔接句、转场、章节钩子 | 宪法 |
| 与账本冲突的数字 | 章节结论与主张 |
| 重复段落的删并 | 事实账本的 `source` / `date` |
| 交叉引用编号 | 依赖声明 |

**两条硬约束：**

1. **事实性错误必须回源。** 发现 Ch08 写 92%、Ch12 写 78%，
   去 `claims.jsonl` 取权威值，把错的一边改成与账本一致。账本没有就补登来源，
   **绝不自己算一个数填进去**
2. **改动预算 20%。** 单章改动超过 20% 正文，或触及结论段，打回原写手重跑。
   缝合 agent 没有章纲的完整上下文，大改必然把文风带偏

### patch 格式

先出清单再落地，不要边看边改：

```
## 波次 3 缝合清单

### ch08
- P1 [术语] 3.2 节「召回」应为「检索召回」（glossary C021）
- P2 [重复] 与 ch05 的 5.3 段重复 4 句 → 删 ch08 部分，改为「见 Ch05」
- P3 [事实] 正文 92% 与账本 F023 一致，ch12 的 78% 需改（转 ch12）

### ch12
- P1 [事实] 92% → 依 F023 改为 92%
```

每波一个 commit，可整体回滚。

## 三、第三级：全书统稿

前面都过了，还有四件只有全书视角才能做的事：

| 专项 | 检查什么 |
| --- | --- |
| 术语归一 | 全书扫一遍，`glossary` 里每条的实际首现章是否等于 `first_chapter` |
| 承诺结清 | `promises.jsonl` 里 `status: open` 必须清零；`dropped` 的要进 FAQ |
| 能力阶梯 | `ladder.jsonl` 是否单调；末章 `after` 是否覆盖所有学习目标 |
| 衔接重写 | 每章「下一章」必须真的对应下一章；统稿阶段的章节顺序可能变过 |

**最后一项最容易被忘。** 章序调过一次，「下一章剧透 Ch09 的内容」就会指向 Ch10，
而这种错机检不出来，只有人（或专门的通读 agent）能发现。

## 四、什么情况下该放弃修复

三种信号说明问题在结构层，继续修只是浪费：

1. 同一章 `repair` 两次仍不过
2. 同一波次里三章以上出现同类术语冲突
3. 缝合时发现某章 20% 以上的内容需要重写

出现任一条，回到阶段 1 改目录或阶段 3 改章纲，不要在正文层打补丁。
